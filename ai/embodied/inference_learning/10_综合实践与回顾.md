## 2. 把"恒等式"记住（阅读代码时的抓手）

- **入口/出口对称**：`apply`（正）↔ `unapply`（逆），只在 `InvertibleModalityTransform` 上发生。
- **双脑分工**：`backbone` 编码"世界语义"，`action_head` 生成"动作"；前者固定输出 `backbone_features`。
- **训练 vs 推理**：`forward`(要 loss) vs `get_action`(只给 action_pred)，backbone 两边一致。
- **生成即去噪**：`actions = actions + dt·velocity`，`num_steps`(denoising_steps) 越多越精细。
- **复用而非重写**：vla_infer 的 ModelVLA 直接调 `Gr00tPolicy`；NPU 加速靠补丁不改结构。

**Q1（第02章）** 归一化与反归一化的目的？为什么必须可逆？

**Q5（第06章）** 流匹配里模型学的是什么（目标量）？推理时怎么用？
**Q6（第06章）** `denoising_steps` 越大，质量和延迟分别怎么变？为什么？
**Q7（第07章）** ZMQ 与 HTTP 两种服务各适合什么场景？
**Q8（第08章）** vla_infer 的 ModelVLA 是重新实现模型还是复用？为什么这样设计？
**Q9（第09章）** transformers_npu 用什么机制让 GR00T 用上 NPU 算子而不改模型源码？

<details>
<summary>点击看参考答案</summary>

- **A1**：让模型在"标准化空间"工作(更稳/更好训)；但要作用于真实机器人必须还原成物理量。可逆是为了
  能对称地"进去再出来"，且 unapply 必须按 apply 逆序执行。
- **A2**：①用哪套归一化统计(metadata)；②用哪个 CategorySpecific 投影器/embedding(由
  EMBODIMENT_TAG_MAPPING 映射到 index)。
- **A3**：训练走 `forward`(返回 loss)；推理走 `get_action`(返回 action_pred)。backbone 两路径相同。
- **A4**：`backbone_features`(语义特征,喂给 DiT 做条件) 与 `backbone_attention_mask`(注意力掩码)。
- **A5**：学"速度场 velocity = x - ε"；推理从噪声出发沿预测速度场做欧拉积分逐步还原动作。
- **A6**：越大→质量越高但延迟越大；因为每步都要过一次 DiT，是线性累积的计算量。
- **A7**：ZMQ 高性能/低延迟/默认，适合实时(机器人与服务同地)；HTTP 易集成/任意语言，适合 Web 等外部客户端。
- **A8**：复用 `Gr00tPolicy`。因为模型逻辑、归一化、去噪都在 gr00t 库，部署层只做数据格式适配与调用，
  避免重复实现、保证一致性。
- **A9**：运行期补丁(`PatchesManager`)：在 from_pretrained 之前把 HF/gr00t 的子模块类/方法替换成
  调用 `groot_ops` 融合算子的 NPU 版(并可回滚)，因此模型结构和外部接口不变。
</details>
